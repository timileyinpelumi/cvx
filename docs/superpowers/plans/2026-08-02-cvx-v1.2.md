# cvx v1.2 Implementation Plan — gap tracker, profile updates, passcode auth

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement task-by-task.

**Goal:** (1) Aggregate gap tracker across all generations; (2) append to the profile by typing what you did, no re-upload; (3) optional passcode auth that activates only when `CVX_PASSCODE` is set.

**Architecture:** All three ride existing seams. Gaps: SQL over the stored `tailored_json` + one UI section. Profile update: one new `ai.LLM` call returning additions, merged server-side with our ID assignment (guardrail intact). Auth: Echo middleware + one in-memory session token + a UI gate state; disabled when the env var is unset so localhost workflow is untouched.

## Global Constraints

- All v1/v1.1 constraints hold: copy rules (sentence case, no em dashes, no exclamation marks, banned words), stitch discipline (no new stitch usage), tokens/8px grid, mono for counts/dates/labels, provider-agnostic `ai.LLM`, guardrail untouched, API backward compatible, idempotent migrations (none needed this round), slog on all error paths.
- Auth must be a no-op when `CVX_PASSCODE` is unset or empty — zero behavior change.
- Profile additions get IDs from our code only (`model.AssignIDs` semantics — new items continue the `item-N` sequence; never model-assigned).
- Copy deck additions (verbatim, the only new user-facing strings):
  - Gap tracker heading: `Recurring gaps`
  - Gap tracker count line (mono): `{n} of {total} roles`
  - Add-to-profile toggle/button: `Add to profile`
  - Add-to-profile placeholder: `Tell cvx what you shipped, learned, or earned`
  - Add-to-profile success: `Added to your profile.`
  - Add-to-profile error: `That didn't save. Try again in a moment.`
  - Login heading: `Enter your passcode`
  - Login button: `Unlock`
  - Login error: `That passcode is wrong. Try again.`

### Task 1: Gap tracker

**Files:**
- Modify: `server/internal/store/store.go` (+tests), `server/internal/httpapi/httpapi.go` (+tests), `web/src/app/page.tsx`, `web/src/app/page.css`
- Create: `web/src/components/GapTracker.tsx`

**Server:**
- `store.GapSummary() ([]GapTrend, int, error)` — reads `tailored_json` of every generation; groups gaps by normalized requirement (lowercase, trim, collapse inner whitespace); returns total generation count and per-group: `GapTrend{Requirement string (original casing of most recent), Count int, Missing int, Weak int, LastEvidence string}` sorted by Count desc then Requirement asc; only groups with Count >= 2 (a gap seen once is noise). json tags: requirement, count, missing, weak, lastEvidence.
- `GET /api/gaps` → `200 {"total": <generationCount>, "trends": [GapTrend]}` (trends always an array, never null). slog on failure.
- Tests: store-level grouping (same requirement different casing groups; count>=2 filter; ordering; lastEvidence from newest), httpapi endpoint shape.

**UI (`GapTracker.tsx`):**
- Rendered under the archive, only when `trends` is non-empty. Heading `Recurring gaps` (same style as `Earlier resumes`).
- Row per trend: requirement (body font, medium) — count line right-aligned mono `{count} of {total} roles`; below the requirement a muted 13px line with LastEvidence; a small severity hint: if Missing > Weak the count line uses `--gap-missing`, else `--gap-weak`.
- Mobile stacks per existing archive stacking rules. No new colors/icons. Fetched with the other loads and refreshed after each generation.
- Commit: `feat: recurring gap tracker`

### Task 2: Profile updates by text

**Files:**
- Create: `server/internal/ai/extend.go` (+tests), `web/src/components/ProfileUpdate.tsx`
- Modify: `server/internal/ai/schema.go`, `server/internal/model/model.go` (+tests), `server/internal/httpapi/httpapi.go` (+tests), `web/src/app/page.tsx`, `web/src/app/page.css`

**Server:**
- Schema + `ai.ExtendProfile(ctx, llm, p model.Profile, note string) (model.ProfileAdditions, error)`:
  - `model.ProfileAdditions{NewSkills []string; NewItems []draft-shaped items (no ids); BulletAdditions []{ItemID string; Bullets []draft bullets}}` json tags camelCase (newSkills, newItems, bulletAdditions, itemId, bullets).
  - System prompt: convert the user's note into profile additions; use ONLY facts stated in the note; never invent employers, dates, metrics; prefer adding bullets to an existing item (reference its exact id from the profile JSON) when the note clearly refers to it, else create a new item; skills only when explicitly evidenced. Strict schema, additionalProperties false everywhere.
- `model.MergeAdditions(p *Profile, a ProfileAdditions) error` — appends: new skills deduped case-insensitively; new items appended with next sequential `item-N` ids and bullets `item-N-b-j`; bullet additions validated against existing item ids (unknown id → error naming it — guardrail spirit), appended with next `item-i-b-j` index. Tests cover id continuation, dedupe, unknown-id error.
- `POST /api/profile/extend` `{"note": string}` → 400 empty note; 409 no profile; on success runs ExtendProfile + MergeAdditions + SaveProfile → `200 {"name","itemCount","skillCount"}` (same summary shape). 502 with error text on LLM failure; slog event `profile extend failed`.
- Tests: fake-LLM endpoint happy path (counts grow), unknown-id 502, empty note 400.

**UI (`ProfileUpdate.tsx`):**
- Under the profile line: a text button `Add to profile` (ink text, no border, 14px, underline on hover) that expands an inline row: single-line input (placeholder `Tell cvx what you shipped, learned, or earned`, 16px on mobile) + primary button `Add to profile` (44px mobile). On success: collapse, show `Added to your profile.` in a `role="status"` line (muted, 13px) for 4s, refresh profile summary. On failure: deck error + mono detail line (existing error-detail pattern).
- Commit: `feat: extend profile from a typed note`

### Task 3: Passcode auth (optional)

**Files:**
- Create: `server/internal/httpapi/auth.go` (+tests), `web/src/components/Passcode.tsx`
- Modify: `server/cmd/cvx/main.go`, `server/internal/httpapi/httpapi.go`, `web/src/app/page.tsx`, `web/src/app/page.css`

**Server:**
- When `CVX_PASSCODE` unset/empty: no middleware registered, no behavior change (test this).
- When set: at startup generate a random 32-byte hex session token (crypto/rand, in-memory). `POST /api/login` `{"passcode"}`: constant-time compare (`crypto/subtle`) → on match set cookie `cvx_session=<token>; HttpOnly; SameSite=Lax; Path=/; Max-Age=2592000` → `204`. Mismatch → `401 {"error":"wrong passcode"}` + slog.Warn. Middleware on all `/api/*` except `/api/login` (and `/healthz` stays open): missing/mismatched cookie → `401 {"error":"unauthorized"}`. Server restart rotates the token (re-login) — acceptable.
- Tests: no-passcode mode fully open; with passcode: unauth 401 on /api/profile, login wrong 401, login right sets cookie and subsequent request passes, /healthz open.
- `server/.env` on disk gains commented `# CVX_PASSCODE=`.

**UI:**
- `page.tsx`: if any bootstrap fetch returns 401 → render `Passcode.tsx` alone (masthead stays): heading `Enter your passcode` (body font 18px semibold), password input (16px mobile, mono), primary button `Unlock` (44px mobile). Wrong → `That passcode is wrong. Try again.` in role=status. Success (204) → reload data, show app. All fetches already same-origin so the cookie just flows.
- Commit: `feat: optional passcode auth`
