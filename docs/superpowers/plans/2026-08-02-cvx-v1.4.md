# cvx v1.4 Implementation Plan — generation quality pipeline

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** Make tailoring quality measurable, then measurably better. An in-repo eval harness (fixed JD fixtures x fixture profile → tailor + cover letter → deterministic checks + LLM-judge rubric → scored report), a baseline, then prompt iterations that only land when scores improve.

**Architecture:** New `server/cmd/cvxeval` CLI reusing the existing `ai.LLM` seam. Fixtures are committed (reproducible); results are timestamped JSON + a rendered table, gitignored except a committed `baseline.json` summary. Judge is a second LLM call with a structured rubric — judge model/provider configurable so the generator never grades itself with the same model.

## Global Constraints

- All prior constraints hold. Nothing in the product runtime changes except prompt text (Task 4) — the harness is dev-only tooling.
- Eval must run with ONLY Groq configured (the current reality): generator = configured provider/model; judge default = Groq `llama-3.3-70b-versatile` (different model family than the gpt-oss generator), overridable via `CVX_EVAL_JUDGE_MODEL` / `CVX_EVAL_JUDGE_PROVIDER`.
- Fixture profile is ANONYMIZED but realistic (modeled on a senior-ish generalist with backend depth) — never the user's real profile, so evals are committable and reproducible.
- Prompt changes land ONLY with a before/after eval delta in the commit message.
- Deterministic checks are code, not judge opinions: guardrail pass, ≤5 items, 2–4 bullets per item, non-empty summary ≤ 60 words, headline non-empty, gaps well-formed, skills subset of profile skills.
- Judge rubric dimensions (0–10 each + one-line rationale): selection (right items for the role), vocabulary (mirrors JD language where profile supports it, no keyword stuffing), bullet strength (specific, outcome-oriented), honesty (nothing beyond profile facts), gap quality (real, actionable), headline+summary aptness. Cover letter (when evaluated): specificity, voice, factuality.

### Task 1: Fixtures

**Files:** Create `server/eval/fixtures/index.json`, `server/eval/fixtures/jd-*.txt` (12 files), `server/eval/fixtures/profile.json`

- 12 real-world job descriptions (400–1500 words each, realistic structure: about/responsibilities/requirements/nice-to-haves) spanning: backend-go, backend-python, backend-node, frontend-react, fullstack, devops-sre, platform, data-engineer, ml-engineer, mobile, web3-solidity, security. Source from real postings (fetch/adapt; strip company-identifying boilerplate, keep the substance). Each file plain text. `index.json`: `[{"id":"backend-go","file":"jd-backend-go.txt","title":"Senior Backend Engineer (Go)"}...]`.
- `profile.json`: a `model.Profile` (with ids, AssignIDs-canonical) for "Alex Okonkwo": 6 items (2 backend-heavy roles, 1 fullstack role, 1 web3 project, 1 open-source project, 1 education), 3–5 bullets each with skills tags, 18 skills. Rich enough that good selection is possible and bad selection is detectable.
- Verification: all files parse (index resolves, profile passes ProfileSchema-equivalent unmarshal + a tiny Go test in `server/eval/fixtures_test.go` loading everything).
- Commit: `feat: eval fixtures — 12 role jds + anonymized profile`

### Task 2: Eval runner

**Files:** Create `server/eval/eval.go`, `server/eval/judge.go`, `server/eval/report.go` (+tests), `server/cmd/cvxeval/main.go`

- `eval.Run(ctx, gen ai.LLM, judge ai.LLM, fixturesDir string, ids []string, coverLetters bool) (Report, error)`: per fixture: `ai.Tailor` (existing prompt, unmodified) → deterministic checks (each pass/fail with reason) → judge call (strict JSON schema: the 6 rubric dims + rationale) → optional cover letter + its 3 dims.
- Judge prompt: given profile JSON, JD text, tailored JSON — score per rubric; explicitly instructed to verify honesty by cross-checking claims against profile facts.
- `Report`: per-fixture scores + failures, aggregate mean per dimension, overall mean, deterministic pass rate. `report.Render(w io.Writer)` — aligned text table. JSON written to `server/eval/results/<UTC timestamp>-<label>.json` (dir gitignored); `-label` flag names the run.
- CLI: `go run ./cmd/cvxeval -label baseline [-ids backend-go,fullstack] [-cover] [-judge-model X -judge-provider Y]`. Uses env for keys (same .env loader).
- TDD with fake LLMs (canned tailored + canned judge JSON); test deterministic checks individually (violations detected); test report aggregation math.
- Commit: `feat: eval harness — deterministic checks + llm judge`

### Task 3: Baseline run (real)

- Run full 12 fixtures + cover letters on current prompts, Groq generator, default judge. Save `-label baseline`; copy the aggregate summary (not per-fixture transcripts) to committed `server/eval/baseline.json`. Present the table + 3 worst dimensions/fixtures in the report to the coordinator.
- Commit: `chore: quality baseline`

### Task 4: Prompt iteration round 1

- Informed by baseline weaknesses: revise the Tailor system prompt (structure: role analysis, selection rules, bullet rewriting guidance, vocabulary mirroring with anti-stuffing rule, gap honesty) and Cover letter prompt. Optional experiment behind env `CVX_TAILOR_TWO_STEP=1`: first LLM call extracts role requirements from the JD, second tailors against them; eval both arms.
- Re-run eval (`-label round1`, and `-label round1-two-step` if applicable). Keep changes ONLY where aggregate improves and no dimension regresses >0.5; two-step becomes default only if it beats single-shot meaningfully (else remove the flag entirely — no dead code).
- All product tests still green (prompt-substring assertions in ai tests may need updating to the new prompt text — keep the assertions meaningful).
- Commit: `feat: tailor prompt v2 (+eval delta in message)`

### Task 5: User gate

- Present before/after: score table + one real side-by-side generation (user's own profile, a role they pick). User judges with their eyes; merge on approval. Provider-comparison run (openai/anthropic) deferred until those keys exist.

## Self-Review
