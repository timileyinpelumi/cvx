# cvx v1.3 Implementation Plan — OAuth sign-in + UI restructure

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** (1) Real auth: Google and GitHub sign-in only, per-user data, passcode feature removed. (2) UI restructure: the single scroll page becomes four views behind a nav (Tailor, History, Gaps, Profile).

**Architecture:** OAuth 2.0 authorization-code flow via `golang.org/x/oauth2` (+ its google/github endpoint subpackages) — no heavier auth framework. Stateless sessions: HMAC-signed cookie (stdlib crypto) carrying user id + expiry. All data rows gain `user_id`; existing rows are adopted by the first user who signs in. Local dev keeps working with zero OAuth setup via `CVX_DEV_USER`.

## Global Constraints

- All prior constraints hold (copy rules, stitch discipline — masthead + result tag only, tokens, 8px grid, mono conventions, provider-agnostic LLM, guardrail, slog on errors, idempotent migrations).
- Only new Go dep: `golang.org/x/oauth2`.
- Auth modes, decided by env at startup:
  - `CVX_DEV_USER=<email>` set → every request auto-authenticates as that user (auto-created). For local dev/tests. Wins over OAuth vars.
  - Otherwise OAuth vars set (`GOOGLE_CLIENT_ID/SECRET` and/or `GITHUB_CLIENT_ID/SECRET`, plus `CVX_BASE_URL`, `CVX_SESSION_SECRET`) → OAuth mode; providers with creds present are offered.
  - Neither → server exits with a clear error naming what to set (auth is no longer optional).
- `CVX_ALLOWED_EMAILS` (comma-separated, optional): when set, only those emails may sign in (others get 403 with a friendly page-level message). When unset, any Google/GitHub account may sign in.
- Passcode feature is REMOVED entirely (auth.go passcode parts, Passcode.tsx, CVX_PASSCODE references, related tests replaced by OAuth tests).
- Copy deck additions (verbatim):
  - Sign-in heading: `Sign in to cvx`
  - Buttons: `Continue with Google`, `Continue with GitHub`
  - Not-allowed error: `This account doesn't have access.`
  - Nav labels: `Tailor`, `History`, `Gaps`, `Profile`
  - Sign out button: `Sign out`
  - Profile view section heading: `Your profile`
  - Replace-resume button: `Replace resume` (reuses upload flow)
  - Empty history: `Nothing here yet. Tailor your first resume.`
  - Empty gaps: `No recurring gaps yet. They show up after a few generations.`
  - Replace-resume uploader body (heading suppressed in that mode — the toggle names the action): `Upload a new PDF. cvx reads it in and replaces the profile it holds now.`
  - Sign-in with no reachable provider list: `Can't reach the server. Reload to try again.`

### Task 1: Auth backend — users, sessions, OAuth flows

**Files:**
- Create: `server/internal/auth/auth.go`, `server/internal/auth/oauth.go`, `server/internal/auth/session.go` (+ tests)
- Modify: `server/internal/store/store.go` (+tests: users table + migration), `server/cmd/cvx/main.go`, `server/internal/httpapi/httpapi.go` (middleware swap), DELETE passcode code in `server/internal/httpapi/auth.go` + its tests
- `server/.env` on disk: replace `# CVX_PASSCODE=` with the new commented vars incl. `CVX_DEV_USER=dev@localhost` (uncommented, so local dev keeps working) and `CVX_SESSION_SECRET=` (generate a random hex value into it).

**Store:**
- Migration (idempotent, PRAGMA-guarded): `users` table (`id INTEGER PRIMARY KEY AUTOINCREMENT, provider TEXT, provider_id TEXT, email TEXT, name TEXT, created_at TEXT, UNIQUE(provider, provider_id)`); add `user_id INTEGER` to `profile` and `generations` (nullable).
- `UpsertUser(provider, providerID, email, name string) (User, error)` — insert or fetch by (provider, provider_id); on FIRST ever user creation, adopt legacy rows: `UPDATE profile SET user_id=? WHERE user_id IS NULL`, same for generations.
- `GetUser(id int64) (*User, error)` — nil,nil when absent.
- `User{ID int64; Provider, ProviderID, Email, Name string}` json tags id/provider/providerId/email/name.

**Sessions (`session.go`):** cookie `cvx_auth` = `base64url(payload)|hex(hmac)` where payload = `userID:expiryUnix`. `Sign(userID, ttl, secret)`, `Verify(cookieValue, secret) (userID int64, ok bool)` — HMAC-SHA256, constant-time compare, expiry checked. TTL 30 days. HttpOnly, SameSite=Lax, Path=/, Secure omitted (localhost HTTP; comment it).

**OAuth (`oauth.go`):**
- Providers built from env: google (`golang.org/x/oauth2/google` endpoint, scopes openid email profile, userinfo `https://openidconnect.googleapis.com/v1/userinfo` → sub/email/name) and github (`golang.org/x/oauth2/github` endpoint, scope `read:user user:email`, userinfo `https://api.github.com/user` + `/user/emails` for primary verified email → id/email/name).
- `GET /auth/:provider/start` → random state (cookie `cvx_oauth_state`, 10min) → redirect to consent. `GET /auth/:provider/callback` → state check → exchange → userinfo → allowlist check (403 + redirect to `/?error=forbidden` when denied) → UpsertUser → set session cookie → redirect `/`.
- Redirect URL: `CVX_BASE_URL` + `/auth/<provider>/callback` (e.g. http://localhost:3000 — Next proxies `/auth/*` too: add the rewrite `/auth/:path*` → `http://localhost:8080/auth/:path*` in `web/next.config.ts`).

**Middleware + routes (`auth.go` in auth pkg, wired in httpapi):**
- Dev mode: every request resolves `CVX_DEV_USER` (upsert provider "dev") and stores userID in context.
- OAuth mode: verify cookie → userID in context; missing/invalid → 401 {"error":"unauthorized"} on /api/*; /auth/* and /healthz open.
- `GET /api/me` → `200 {"id","email","name","provider"}`; `POST /api/logout` → clears cookie, 204.
- Providers list for the UI: `GET /auth/providers` → `{"providers":["google","github"]}` (only those configured; open route).

**Tests:** session sign/verify round-trip + tamper + expiry; middleware dev mode; OAuth callback with a fake provider server (httptest for token + userinfo endpoints, config override); allowlist deny; adoption migration (legacy rows get first user's id; second user doesn't re-adopt); /api/me; logout. Passcode tests deleted.
