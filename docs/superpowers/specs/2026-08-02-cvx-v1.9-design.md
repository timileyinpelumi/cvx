# cvx v1.9 — Recruiter-ready email

Backlog item: when generating, the user can ask for a recruiter-facing
email in their own inbox — application note in first person, resume (and
cover letter) attached, clean enough to forward untouched. Opt-in per
generation via a checkbox; unchecked keeps today's private notification.

## Scope

In: `ai.RecruiterEmail` generation, `mail.SendRecruiter`, `recruiterEmail`
flag through generate request/response, second checkbox in the Generator,
result-tag note.
Out: persistence of the email text, editing UI, sending directly to a
recruiter address, settings entries, changes to the notification email.

## 1. Generation (ai)

- `model.RecruiterEmail { Subject string; Paragraphs []string; Closing
  string }` (json `subject`, `paragraphs`, `closing`).
- `ai.RecruiterEmail(ctx, llm, p model.Profile, roleInput string)
  (model.RecruiterEmail, error)` — one LLM call, JSON schema with
  `additionalProperties: false` and all fields required.
- Prompt rules (binding):
  - First person, written as the candidate applying for this role.
  - 3 to 5 sentences total, one or two short paragraphs. An email, not a
    letter: no date, no addresses, no "Dear hiring manager" heading — a
    plain conversational opening line is the first paragraph.
  - Honesty standard of the cover letter: every claim traceable to the
    profile JSON; never invent employers, metrics, dates, or skills.
  - Use the role's own vocabulary only where the profile supports it.
  - Subject in the shape `Application for <role title>` (role title from
    the posting; keep it under 80 characters).
  - `closing` is a short sign-off (for example "Best regards,") — the
    candidate's name is appended by the renderer, not the LLM.
  - No placeholder brackets, no em dashes, no exclamation marks.

## 2. Sending (mail)

- `mail.SendRecruiter(to string, subject string, paragraphs []string,
  name string, pdf []byte, filename string, endpoint string, extra
  ...Attachment) (bool, error)`.
- Same gate as `Send`: returns (false, nil) without a network call when
  `RESEND_API_KEY` unset or `to` empty. Same from-address resolution,
  timeout, endpoint override for tests.
- Body: each paragraph as `<p>`, then closing + name. Nothing else — no
  gaps, no what-changed, no cvx framing. HTML-escaped throughout.
- Attachments: resume PDF always; cover letter PDF via `extra` when the
  generation produced one.

## 3. Wiring (httpapi + main)

- `generateRequest` gains `RecruiterEmail bool` (json `recruiterEmail`).
- `generateResponse` gains `RecruiterEmail bool` — true only when the
  recruiter email was actually sent.
- `postGenerate`, email step:
  - Flag off → exactly today's notification path.
  - Flag on and user has an email → call `ai.RecruiterEmail`; on success
    send via `SendRecruiter`; `emailed` and `recruiterEmail` reflect the
    send result.
  - `ai.RecruiterEmail` failure → log `recruiter email failed`, send
    NOTHING (no fallback to the notification — the user asked for a
    specific artifact), `emailed: false`, generation still returns 200.
- `Server.Mail` stays as is for the notification; a second injectable
  `Server.RecruiterMail func(to, subject string, paragraphs []string,
  name string, pdf []byte, filename string, coverPDF []byte,
  coverFilename string) (bool, error)` wraps `mail.SendRecruiter` in
  main.go, so tests fake both independently.

## 4. UI (web)

- Generator: second option row under the cover letter checkbox, label
  `Recruiter-ready email`. Sent with the request; captured into the
  regenerate state like the other inputs (v1.8's `submitted` gains the
  flag).
- Result tag: when the response has `recruiterEmail: true`, the note
  reads `A recruiter-ready email is in your inbox.` (replacing the
  `Sent to your inbox too.` note for that generation). `emailed: true`
  without the flag keeps today's note.

## Copy (exact strings)

- Checkbox label: `Recruiter-ready email`
- Result note: `A recruiter-ready email is in your inbox.`

## Constraints (binding)

- Honesty: profile-only claims in the email body; no tailor/eval changes.
- Resend caveat stands: with the default `onboarding@resend.dev` sender,
  Resend only delivers to the account owner's address until a domain is
  verified.
- Design system and copy rules as every release.
- Branch `feat/v1-9`, merge `--ff-only`.

## Testing

- ai: fake LLM captures system prompt and blocks (profile JSON + role
  text present); response unmarshals into RecruiterEmail.
- mail: httptest server asserts auth header, subject passthrough, body
  contains paragraphs and name, attachments count (1 without cover, 2
  with), and body contains no `Gaps` / `What changed` strings; gate
  returns (false, nil) with no key.
- httpapi: flag on → RecruiterMail fake called with LLM subject and the
  response carries `recruiterEmail: true`; flag off → notification fake
  called, recruiter fake untouched; RecruiterEmail LLM failure → 200,
  `emailed: false`, neither mail fake called (recruiter path) — assert
  notification NOT sent as fallback.
- web: `bun run build`; manual pass of both checkbox states.
