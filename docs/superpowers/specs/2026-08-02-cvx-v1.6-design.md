# cvx v1.6 — App shell and archive design

Frontend-only release. No backend changes. Goal: cvx feels like an installed
app, not a website, and the archive becomes genuinely useful. Stay close to
the existing design system — this is a frame swap and one view enriched, not
a redesign.

## Scope

In: app frame, grid-icon nav popover, archive enrichment, installable PWA.
Out (unchanged): generation flow, result tag, profile view, gap tracker
content, sign-in, all of `server/`.

## 1. App frame

- The page is a fixed-height shell: `height: 100dvh`, flex column. The
  masthead is pinned at the top; the content region below it is the only
  scroll container (`overflow-y: auto`). The document body never scrolls.
- Mobile Safari quirks: use `100dvh` (not `100vh`), and
  `overscroll-behavior: contain` on the scroll region so rubber-banding
  stays inside the app.
- Everything inside the content region keeps its current layout, spacing,
  and max-width.

## 2. Grid-icon nav

- The tab row is removed. The masthead becomes: wordmark + stitch motif on
  the left, one icon button on the right.
- The button uses the Lucide `LayoutGrid` icon (the four-squares grid),
  size 20, `aria-label="Views"`, `aria-haspopup="menu"`, `aria-expanded`.
- Clicking opens a popover card anchored under the button, right-aligned:
  the four views (Generate, Profile, Archive, Gaps) listed vertically, each
  row an icon + name using the same Lucide icons the tabs used. The current
  view row is marked (chalk-colored icon + text, subtle background).
- Behavior: click outside closes, Escape closes and returns focus to the
  button, ArrowUp/ArrowDown move through items, Enter/Space selects. Role
  semantics: `role="menu"` / `role="menuitem"`.
- Selecting a view closes the popover and switches views exactly as the
  tabs did (same state in `page.tsx`, no routing change).
- The popover is a plain positioned div with a shadow token — no portal
  library, no dependency.

## 3. Archive enrichment

`/api/generations` already returns everything needed per row: `targetRole`,
`createdAt`, `gaps` (with severity), `hasCoverLetter`, `filename`.

- Each generation renders as a card row:
  - Role title (body face, medium weight), created date in mono.
  - Gap indicator: one dot per gap — `--gap-weak` amber for weak,
    `--gap-missing` red for missing — followed by a mono count. No gaps
    renders nothing (absence is the signal).
  - A small `Mail`-adjacent marker is NOT used; cover letter presence is a
    quiet mono label "cover letter" next to the date.
  - Actions: a download button for the resume PDF and, when
    `hasCoverLetter`, one for the cover PDF. Lucide `Download` and
    `FileText` respectively, with text labels on desktop, icon-only with
    `aria-label` under 480px.
- Search: a text input above the list filters rows by `targetRole`,
  case-insensitive substring, as you type. Client-side only.
  - Placeholder: `Filter by role`.
  - No results copy: `No generations match that role.`
  - The input only renders when the archive has more than one generation.
- Empty archive keeps its existing copy.

## 4. Installable PWA

- `web/src/app/manifest.ts` (Next.js metadata route): name `cvx`,
  short_name `cvx`, `display: "standalone"`, `background_color` paper
  `#EEF0EF`, `theme_color` paper `#EEF0EF`, start_url `/`.
- Icons: 192 and 512 PNGs generated once from the existing logo mark
  (chalk mark on paper background), stored in `web/public/`. The existing
  `icon.svg` stays as favicon.
- No service worker, no offline mode, no install prompt UI. The browser's
  own install affordance is enough.

## Constraints (binding, from the existing brand system)

- Tokens only — no new colors, radii, or fonts. Shadows may add one token
  (`--shadow-pop`) for the popover if none exists.
- Lucide icons only. Copy: sentence case, no em dashes, no hyphens used as
  dashes, no exclamation marks, banned marketing words per the copy deck.
- Mobile responsive and desktop equally good. Keyboard and screen reader
  parity for the nav popover (it replaces a tablist — the replacement must
  not be less accessible).
- `bd`/plan conventions: work on branch `feat/v1-6`, merge `--ff-only`.

## Testing

- Component behavior is verifiable by hand (popover keyboard flow, search
  filtering, frame scroll) — the web app has no test harness and v1.6 does
  not add one.
- `bun run build` must pass clean; manual pass on 360px, 768px, 1280px
  widths; install-to-desktop verified in Chrome.

## Backlog captured (not in v1.6, priority order given by user)

1. PDF system overhaul: theme options, style options, content organization,

2. Gap fill-in: each gap on a result gets a button that opens an optional

3. Settings page with tunable generation parameters.
4. Recruiter-ready email: generation can send a complete recruiter-facing
