# cvx v1.8 — Gap fill-in

Backlog item 2. A gap on a result or in the tracker gets a "Fill in"
button: the user types what their real experience is, the AI folds it into
the profile through the existing extend pipeline, and a fresh generation is
one click away.

## Scope

In: optional `context` on `/api/profile/extend` + `ai.ExtendProfile`,
"Fill in" inline input on result-tag gaps and gap-tracker rows, filled
state, "Generate again" on the result tag.
Out: new endpoints, tailor prompt changes (no eval gate needed — the
tailor path is untouched), editing or deleting profile content, tracking
filled state server-side.

## 1. Backend: extend with context

- `extendRequest` gains `Context string` (json `context`, optional).
- `ai.ExtendProfile(ctx, llm, p, note, gapContext string)` — signature
  gains the context; empty string means today's behavior exactly.
- When non-empty, the context is passed as an extra content block:
  `"The user is answering this gap from a recent generation:\n<requirement — evidence>"`
  and the system prompt gains one rule: context may guide the wording and
  placement of additions toward that requirement, but additions may only
  contain what the note itself claims. A note that does not support the
  requirement produces additions for what it does support, or nothing.
- The honesty rule of the extend prompt is binding and unchanged: nothing
  enters the profile that the user's note does not state.
- `model.MergeAdditions` guards ids exactly as today.
- Handler: passes `req.Context` through; absent context is the empty
  string. No other endpoint changes.

## 2. Result tag: fill in and regenerate

- Each gap row gains a `Fill in` button (quiet text button, chalk).
  Clicking it swaps the row's action area to an inline form: one text
  input, placeholder `What is your real experience here`, and an `Add`
  button (primary). Enter submits, Escape closes.
- Submit posts `/api/profile/extend` with the note and
  `context: "<requirement> — <evidence>"`. Busy state disables the input.
- Success: the form closes, the row shows a mono `added to profile` note,
  its severity dot goes edge-colored, and the parent refreshes the profile
  summary (item and skill counts may change). Failure: the standard error
  notice + detail inline under the row.
- Filled state lives in component state only — it is a session affordance,
  not persisted.
- Once one or more gaps are filled, the result tag shows a `Generate
  again` button. It calls a `onRegenerate` callback; the Generator
  re-posts `/api/generate` with the role input it already holds and the
  same cover letter choice, replacing the result. The prior generation
  stays in the archive untouched.
- If the role input has been cleared or edited since (the user typed a new
  role), `Generate again` simply is not shown — the affordance belongs to
  the result it sits on. Concretely: the Generator captures the submitted
  role input at generate time and regenerates from that captured value.

## 3. Gap tracker: fill in

- Each trend row gains the same `Fill in` button and inline form. The
  context sent is `"<requirement> — <lastEvidence>"`.
- Success: form closes, the row shows the same `added to profile` mono
  note for the rest of the session, and the profile summary refreshes.
  The tracker data itself is historical aggregation and is not reloaded
  or rewritten by a fill.
- No regenerate offer in the tracker (no active role there).

## Copy (exact strings)

- Button: `Fill in`
- Placeholder: `What is your real experience here`
- Submit: `Add`
- Success note: `added to profile` (mono, muted)
- Regenerate button: `Generate again`
- Failure: reuse `That didn't save. Try again in a moment.` + detail line.

## Constraints (binding)

- Anti-fabrication: the extend prompt's note-only rule wins over the gap
  context in all cases; `ValidateTailored`/`MergeAdditions` guardrails
  untouched.
- Design system: tokens, Lucide only, flat rows, no cards, no dropdowns,
  sentence case, no em dashes or exclamation marks in copy.
- Branch `feat/v1-8`, merge `--ff-only`.

## Testing

- ai: ExtendProfile with context includes the context block and the
  targeting rule reaches the system prompt (fake LLM captures inputs);
  with empty context the prompt blocks are byte-identical to today's.
- httpapi: extend accepts `context`, works without it; response shape
  unchanged.
- web: `bun run build`; manual — fill a gap from a result, watch counts
  bump, regenerate against the updated profile, fill from the tracker,
  360px layout.
