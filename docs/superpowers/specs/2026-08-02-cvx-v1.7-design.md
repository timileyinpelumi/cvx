# cvx v1.7 — PDF themes, style, content floor, settings view

Backlog item 1 (PDF system overhaul) plus the seed of item 3 (settings).
Goal: the PDF stops being one hardcoded look — three deliberate themes, a
short list of style knobs saved per user, a content-fullness rule on the
generator, and a Settings view to hold it all.

## Scope

In: style model + per-user storage, settings API + preview endpoint,
data-driven theming in `pdfgen` (resume and cover letter), Classic/Modern/
Compact themes, accent + density + section order knobs, tailor prompt
content floor (eval-gated), fifth nav view "Settings".
Out: layout auto-fit (rejected — content floor only), per-generation style
override (per-user default only), any other settings beyond resume style,
template galleries (never list).

## 1. Style model and storage

- `pdfgen.Style`:
  - `theme`: `"classic" | "modern" | "compact"` (default `"modern"`)
  - `accent`: one of exactly six hex values (default chalk):
    `#1C2422` (ink, reads as no-accent), `#2244D9` (chalk), `#0F766E`
    (teal), `#7C2D92` (plum), `#B3341E` (rust), `#B07818` (bronze)
  - `density`: `"normal" | "tight"` (default `"normal"`)
  - `skillsFirst`: bool (default false — experience first)
- Storage: new table `user_settings (user_id INTEGER PRIMARY KEY,
  resume_style TEXT NOT NULL)` holding the style as JSON. Idempotent
  migration in `store.Open` like the existing ones. JSON blob so the later
  settings page adds keys without schema changes.
- Store methods: `GetResumeStyle(userID) (json.RawMessage, error)`
  (nil when unset), `SaveResumeStyle(userID int64, style json.RawMessage)
  error` (upsert).
- Server-side validation is the source of truth: every field checked
  against the allowed sets; anything invalid or missing resolves to its
  default (never an error for missing — settings are optional).

## 2. API

- `GET /api/settings` → `{"resumeStyle": {theme, accent, density,
  skillsFirst}}`, defaults when unset. Auth-guarded like the rest.
- `PUT /api/settings` with the same shape → validates, saves, returns the
  saved (normalized) style. Unknown values → 400 with the standard error
  JSON.
- `GET /api/settings/preview` → renders a sample resume PDF from the
  user's real profile with their saved style, `Content-Disposition:
  inline` so it opens in the browser rather than downloading. The sample
  Tailored is synthesized in code (no LLM call): headline "Sample resume",
  first up to 4 profile items in stored order with up to 3 bullets each,
  full skills list, no gaps or whatChanged. 404 when no profile exists.
- `/api/generate` loads the user's style once per request and passes it to
  both `pdfgen.Render` and `pdfgen.RenderCoverLetter`.

## 3. pdfgen theming (data-driven, one renderer)

- `Render(p, t, style Style)` and `RenderCoverLetter(p, cl, role, style
  Style)` — signature change; all call sites updated.
- Internally a `theme` config struct resolved from `Style`: display font
  family, body font family, name pt, section title pt, body pt, leading
  factor, margins, section gap, item gap, accent RGB, rules on/off,
  `twoColSkills` flag. The render pipeline reads only from the config;
  no `if theme == X` branches outside config resolution and the skills
  renderer.
- Density "tight" applies a fixed multiplier step to leading and gaps
  within any theme; Compact already sits tighter, so tight Compact is the
  densest legal output.
- `skillsFirst` swaps the skills section ahead of the first item section.
- Fonts: Source Serif 4 Regular + SemiBold TTFs vendored into
  `server/internal/pdfgen/fonts/` beside the existing Source Sans 3 files,
  registered via the same `go:embed` path. Classic uses serif for name and
  section titles only; body stays Source Sans for legibility.
- Theme values:
  - **Classic**: margins 20/18mm, name 20pt serif SemiBold ink, section
    titles 11pt serif SemiBold with a hairline rule under each (accent),
    body 10pt, leading 1.4. Accent used on rules and name only.
  - **Modern**: margins 18/16mm (unchanged), name 19pt sans SemiBold in
    accent, section titles 10.5pt sans SemiBold accent, body 10.5pt (up
    from 10), leading 1.35, extra 2mm before each section title. The
    legibility pass: bullet indent and gap tuned so wrapped bullet lines
    align cleanly.
  - **Compact**: margins 16/14mm, name 17pt, section titles 9.5pt, body
    9.5pt, leading 1.25, skills rendered in two balanced columns.
- Cover letter uses the same fonts, accent, and margins as the chosen
  theme; body copy stays 10.5pt everywhere for readability.
- The existing orphan-control and long-title wrap logic is preserved and
  reads its thresholds from the theme config.

## 4. Content floor (eval-gated)

Tailor prompt addition, replacing nothing: when the profile contains more
genuinely relevant evidence than the current selection, prefer the fuller
selection — for on-domain roles target 4-5 items carrying 3-4 bullets
each before stopping. The existing rules still dominate: never pad with
weak items, never stretch bullets, stretch roles may stay short with gaps
carrying the difference.

Gate (binding, from v1.4): run `cmd/cvxeval` before and after; land only
if overall improves AND no dimension regresses more than 0.5 vs
`server/eval/baseline.json` (8.51). The prompt change and any eval/judge
change must never land in the same gated change.

## 5. Settings view (web)

- Fifth nav item in both variants: Lucide `SlidersHorizontal`, label
  `Settings`, view id `settings`.
- One group, "Resume style", flat rows in the existing design system (no
  cards):
  - Theme: three radio rows — `Classic` / `Modern` / `Compact`, each with
    a one-line muted description:
    - Classic: `Serif headings, quiet rules, traditional.`
    - Modern: `Clean sans with an accent. The default.`
    - Compact: `Smaller and tighter, for full profiles.`
  - Accent: a row of six color dots (36px targets, `aria-label` per color
    name: Ink, Chalk, Teal, Plum, Rust, Bronze); the active dot gets a
    ring.
  - Density: radio pair `Normal` / `Tight`.
  - Order: radio pair `Experience first` / `Skills first`.
- Every change saves immediately (PUT); a quiet mono `Saved.` appears in a
  notice slot and fades after a few seconds. Save failure shows the
  standard error notice plus detail line.
- `Preview PDF` link (opens `/api/settings/preview` in a new tab) under
  the group, so a theme can be judged without spending a generation.
- Settings load at boot with the other loaders; 401 handling identical.

## Constraints (binding)

- Tokens, Lucide icons, copy rules (sentence case, no em dashes, no
  exclamation marks, banned marketing words) as in every release. New copy
  strings are exactly the ones quoted in this spec.
- No new Go dependencies: fpdf + vendored TTFs only. No card surfaces; no
  dropdowns.
- Eval gate as stated in section 4.
- Branch `feat/v1-7`, merge `--ff-only`.

## Testing

- store: settings round-trip, per-user scoping, invalid JSON tolerated at
  read (falls back to defaults at the API layer).
- pdfgen: per-theme render smoke tests (non-nil PDF, parses as PDF, one
  page for the standard fixture), two-column skills renders all skills,
  accent and density change output bytes, cover letter accepts every
  theme.
- httpapi: GET defaults, PUT round-trip + 400 on bad values, preview needs
  auth, 404 without profile, generate uses saved style (spy on pdf bytes
  differing between two styles).
- eval: before/after run for the content floor with delta table in the
  commit message.
- web: `bun run build`; manual pass on all five views at 360/768/1280px.
